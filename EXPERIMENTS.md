# Как проверялась wiki

Эксперименты проводились 19–23 ноября 2026 года на Apple M4 с 16 ГиБ памяти. Они начинались с задачи для двух участников. Один обновляет регламент по принятому решению, другой позже находит действующее правило и проверяет его основание. Для измерения поиска и качества ответов использовался открытый синтетический корпус EnterpriseRAG-Bench v1.0.0. [Демо правки](demo/p/orbit-guide/v2.html#s1) · [Исходный корпус](https://github.com/onyx-dot-app/EnterpriseRAG-Bench/releases/tag/v1.0.0)

## MVP. Что именно передавать модели

Из двух срезов импортированы 5 189 wiki-страниц. Для 64 английских вопросов в срезе нашлись все эталонные документы. Для 30 из этих вопросов подготовлены русские формулировки. На одинаковых карточках длиной до 440 символов SQLite FTS5 нашёл хотя бы один эталон в первых пяти для 44/64 английских вопросов, лексический XERJ — для 45/64, XERJ с multilingual-E5 и объединением рангов RRF — для 43/64. На русских запросах у каждого метода 1/30. Для этих запросов точный поиск по векторам в NumPy дал ту же пятёрку по составу, что и XERJ. [Исходные выдачи](results/retrieval.json) · [Контроль векторов](results/dense.json)

В отдельном опыте SQLite искал по полным разделам. Среди пяти разделов нашёлся эталон для 50/64 английских вопросов. Для этих попаданий чтение одного раздела потребовало суммарно 32 546 токенов, чтение всей соответствующей редакции — 103 554. Достаточность отрывка для ответа в этом опыте не оценивалась. [Результат поиска](results/fulltext.json) · [Замеры размера ответа](results/payload.json) · [Трассы пяти сценариев редактирования](results/agents-sqlite.json)

## Пять этапов

| Этап | Что было проверено | Где посмотреть |
|---|---|---|
| 1. Парный сценарий | На трёх одинаковых документах обе системы нашли нужное решение, обновили инструкцию и позволили агенту в новом диалоге проверить правку. В итоговом прогоне поиск дал 3/3 на обеих сторонах. Правка с проверкой заняла 104,62 с у XERJ и 90,81 с у Confluence. Размер обозначает объём исходного текста. Эти два нагрузочных прогона выполнены только для XERJ. ## Почему сравнение поиска пришлось повторить

HTML-импорт полного корпуса в Confluence завершился частично. Для сопоставимого теста собраны 512 одинаковых страниц, включая 132 разных эталона. Перед запуском проверены ID страниц и нормализованный текст каждого эталона. На 64 вопросах выборочный запрос CQL дал 3 попадания, широкий запрос CQL — 0. Это характеризует две конкретные формулировки CQL. Затем провели самостоятельный тест семантического инструмента Rovo `search` с оригинальным текстом вопроса. [Манифест 512 страниц](benchmarks/pages.csv) · [Оценки CQL по вопросам](results/retry-2026-11-22/paired-search-selective.json) · [Широкий CQL](results/retry-2026-11-22/paired-search-all-terms.json)

| На тех же 64 английских вопросах | XERJ, лексический MCP | Rovo, семантический MCP |
|---|---:|---:|
| Вопросы с эталоном в top-5 | 56 | 52 |
| Средняя доля найденных эталонов в top-5 | 79,9% | 75,6% |
| Медиана времени одного вызова, видимая клиенту | 5,72 мс | 1 087,27 мс |

В 50 вопросах обе системы нашли эталон, в шести его нашёл только XERJ, в двух только Rovo, ещё в шести обе промахнулись. Парный bootstrap дал 95%-й интервал для разницы от −1,56 до +14,06 п. п. XERJ работал по loopback. У Rovo в задержку вошли сеть и OAuth-мост. Поиск Rovo был ограничен приложением Confluence на сайте. Все полученные позиции первой пятёрки сопоставились с общим корпусом, хотя индекс облачной системы мог быть шире. [64 пары, порядок и длительности](results/rovo-2026-11-22/paired-search.json)

## Что произошло после поиска

Для 16 вопросов заранее выбраны восемь задач с одним и восемь с несколькими источниками. Строгая проверка требовала всех обязательных фактов, подтверждения утверждений и проверяемых ссылок. Обе стороны работали с одной Qwen3-4B. Чтение в использованном сеансе Atlassian выполнялось через `getConfluenceContent`. Каждая строка ниже представляет отдельный запуск.

| Версия общего клиента | Полные ответы XERJ / Rovo | Медиана времени задачи XERJ / Rovo |
|---|---:|---:|
| Первый пилот, до двух поисков | 1/16 · 1/16 | 48,75 с · 65,58 с |
| До пяти поисков, проверка ссылок до сдачи | 1/16 · 0/16 | 71,18 с · 76,99 с |
| План по вопросу и точная цитата для каждого утверждения | 1/16 · 0/16 | 180 с · 180 с |

В последнем прогоне у каждой стороны 10 тайм-аутов. При контроле с уже подобранными выдержками 4B и 8B решили одни и те же три из восьми задач. Среди оставшихся ошибок — повторный подсчёт одного документа и потеря условий процедуры. Смысловую оценку выставлял Codex по обезличенным ответам. Некоторые примеры уже были знакомы проверяющему. Независимое ревью Kimi относилось к коду. Один прогон на условие и отсутствие сравнительного исследования с людьми ограничивают выводы о надёжности агента и удобстве интерфейса.
